# 上游谱聚类实现的具体问题

此文是对原论文历史实现的诊断记录，不判断上游论文全部公式或其他实现。
当前代码已删除该谱实现及其选择入口，统一使用 igraph Newman；下文的代码路径、
行号和失败测试均针对历史快照。历史源码可从论文提交
`356c1852c65a185b05aed040052c5c3f750991bd` 获取。

源文件与 JPMorganChase 上游提交
`454f151e02c3a652b1a56162999a844b4ec9699f` 逐字节相同，来源核验见
[依赖溯源](../third_party/dcmppln.VENDORED.md)。小图矩阵、递归轨迹和数值检查见
[诊断数据](spectral-implementation-diagnostics.json)。

索引混用和负得分未撤销属于直接的实现错误。矩阵与增益公式部分则明确以标准
Newman 模块度递归为核对对象；“modified” 可以意味着另行设计的启发式，若原论文
定义了不同目标，还需按其原文逐项核对，不能仅因不同于标准形式就断言整篇原论文
的数学推导错误。这里没有作这种扩大的判断。

## 1. Louvain 名称与实际执行路径

`dcmppln/clustering.py` 中，`clustering_method="louvain"` 经
`_call_louvain()` 调用 `modularity_spectral_optimization()`；默认
`max_community_size=0`。后者构造模块度矩阵，求最大特征值对应的特征向量，
按分量正负递归二分。这是 Newman 风格的谱模块度二分，不是 Louvain 的
节点贪心移动与社区聚合过程。两者都使用模块度，不代表是同一个算法。

上传的 CAF 论文正文已经使用 “modified spectral clustering based on Newman's
method” 和 “upstream spectral community-detection pipeline” 的表述，但图 2
仍标 “RMT + Louvain”。上游仓库 README 也明确写 modified spectral clustering。
因此可确认的是配置名、图示与实际算法存在命名不一致，不能据配置名推断原 JPM
论文声称采用 Louvain。本次没有逐页核验那篇原始论文。

## 2. 社区标签写回时混用局部位置与全局节点编号

谱函数 48–49 行得到的是当前子图特征向量中的位置。
54–55 行却直接执行 `partition[positive_indices] = ...`，把这些位置当作
全图资产编号。56–57 行虽然正确生成了 `current_subgraph[positive_indices]`，
标签写回时没有使用它。

例如子图节点是 `[10,20,30]`，正号位置是 `[0,2]`，应更新全图资产 `[10,30]`，
原代码却更新资产 `[0,2]`。根节点最初是 `arange(N)`，因此第一层常看不出问题；
后续递归中位置与资产编号分离，错误才显现。输出仍可能覆盖全部资产、每个资产
也只有一个标签，但不再对应刚刚计算出的递归分裂。

## 3. 计算子图分裂得分时再次发生相同索引错误

63–64、68–69 行直接用 `positive_indices` / `negative_indices` 切全图邻接矩阵
及全图度向量。此处应该使用对应的全局节点集合。它与标签写回错误影响不同：
前者改变分裂/停止判据的输入，后者把已算出的分裂写到了错误资产上。

16 节点测试图中，程序递归到节点 `[8,...,15]` 时，局部正号位置 `[4,5,6,7]`
应对应 `[12,13,14,15]`，但得分与写回都用了全图 `[4,5,6,7]`。

## 4. 广义模块度矩阵的对角修正不符合标准 Newman 递归定义

令非负对称邻接矩阵为 A，节点度为 k_i，T=sum(A)。标准模块度矩阵为

`B_ij = A_ij - k_i*k_j/T`。

对当前节点集 G，标准递归二分使用

`B_G = B[G,G] - diag(B[G,G] @ ones)`。

行和修正让该子图不分裂时的增益基准为零。原代码 18–19 行用的是

`diag correction_i = sum_{j in G}(A_ij) * k_i / T`，

而正确的行和是

`sum_{j in G}(B_ij) = sum_{j in G}(A_ij) - k_i*sum_{j in G}(k_j)/T`。

两者一般不相等。对全图根节点，标准 B 行和为零，本来不需要额外修正，原代码
却再减去 `diag(k_i**2/T)`。节点度不同时，该修正会影响谱松弛的特征向量。
尽管仅改变对角线对直接枚举 +/-1 向量的相对二次型值只贡献常数，这里先求连续
特征向量，再取符号，不能把非均匀对角改动直接当作无害常数。

16 节点测试中，标准根矩阵最大绝对行和约 1.1e-15，原实现约 0.225116。

## 5. 分裂得分不是模块度增量，且负得分没有撤销分裂

对符号向量 s，标准二分模块度增量是

`Delta Q = s.T @ B_G @ s / (2*T)`。

等价地，用原图 B 子块求和，是“两个子社区内部之和，减去原父社区内部之和”，
再除以 T。73 行的 `Qg=(sum(B_pos)+sum(B_neg))/T` 没有按这一定义计算差值，
且使用了前述错误矩阵和节点。它不能作为标准递归模块度增益使用。

独立的控制流问题是：54–55 行先改标签，59–60 行先添加子图，78 行之后发现
`Qg<=0` 时只删除未来待递归子图，没有恢复标签。因此负得分只停止进一步分裂，
并没有真正拒绝本次已提交的分裂。

保存的 12 节点非负对称加权图实例中，某次拟议分裂的真实增量为
`-0.0003435835933`，代码自己的 `Qg=-0.007229228338` 也为负，但标签仍被改写。
这不是仅由理论推测得到的未覆盖分支。

标签生成还有额外风险：前两次分裂分别使用标签 `(1,2)` 和 `(2,3)`。
第二次的新标签 2 可能与其他尚未更新的社区标签 2 冲突。最终 `np.unique`
只能重编号，不能把已混为同一标签的不同社区重新区分。

## 6. 可观察后果及主基准边界

16 节点层次图包含四个 4 节点强连接块。原实现返回两个 4 节点社区和一个
8 节点社区；重排节点顺序、保持图不变后，映射回原编号的结果又变成了四个
混合社区。归档修复实现返回四个预期块，且在该置换下保持相同节点集合。
置换检查是辅助证据，索引赋值的语义本身已经足以确定上述错误。

论文 2016 数据上，旧实现与修复研究的模块度分别为 0.024676、0.167819；
社区大小分别为 `[101,96,92,81,49,38,14,11,2]` 和 `[199,153,132]`。
这些差异属于该数据与修复组合的结果，不能推广为正确谱聚类永远应输出 3 个社区。

配对实验中，旧划分对应平均 CAF 改进 6.589791%，归档修复划分对应 1.802886%。
这同时改变社区预算、局部规模和总采样分配，不能把性能差异单独归于某一个
索引修复，也不能据此否定 CAF 的上下文公式。模块度更高也不保证最终金融目标更优。

## 7. 仅限可选大小限制分支的其他问题

`modularity_spectral_threshold()` 的 104 行先计算常规划分，139–140 行却从
全图节点重新开始，前面的划分没有作为实际起点。131–132 行在单侧为空时直接
返回当前大社区，所以 threshold 不是严格大小上限。零权图可出现除零/NaN，
受限分支的特征分解可能失败；空图也没有正常处理。缺少方阵、对称及非负输入
校验属于接口健壮性不足，应与正常输入上的数学/索引错误分开讨论。

论文历史主基准用 `max_community_size=0`，不调用这个大小限制分支。旧测试套件中的
9 项预期失败是上述问题的测试案例数，包含参数化输入，不是 9 种独立数学错误。
这些测试已随旧实现退役，当前 igraph 路径使用正常执行的检查。
